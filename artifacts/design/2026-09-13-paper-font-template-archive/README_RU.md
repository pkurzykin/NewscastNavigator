## Сценарий: R-009/R-010

- Сохранён утверждённый стиль: тёплый фон, Onest для UI, PT Sans как пример текста, ширина 1294 px, отступы 36 px, синяя шапка и пять столбцов таблицы.
- Справа в первой строке инструментов добавлен компактный выбор **«Шрифт сценария — PT Sans / Franklin Gothic Book»**. На макете выбран PT Sans. Он меняет наследуемый основной шрифт сценария, а не ручные настройки фрагментов.
- Во второй строке существующий выбор получил подпись **«Фрагмент»** и значение **«Основной (PT Sans)»**. При раскрытии должны остаться все шесть существующих гарнитур; наследование основного шрифта — отдельное состояние, позволяющее вернуться к нему. Открытое меню этой итерацией не отрисовано. Название текущего поля рядом с операциями помогает понимать область применения.
- Жирность, курсив, зачёркивание, цвет, заливка и вручную выбранные шрифты сохраняются. Моноширинные таймкоды и UI не подчиняются основному шрифту сценария. Набор и настройки редактора не сокращаются до двух гарнитур.
- Новый сценарий показан с четырьмя пустыми блоками: **Подводка → ЗК → СНХ → ЗК**. Имя спикера/должность в СНХ и подсказки текста — placeholders, не сохраняемые данные. Стартовый набор создаётся один раз; повторное открытие его не добавляет.
- На холсте показан сценарий после входа в редактирование: взята существующая визуальная полоса «Вы редактируете» с включённым переключателем. Простое открытие карточки не должно занимать lease; это отдельное правило из R-007/R-008.
- При пустом тексте «Текст готов» показана недоступной, хронометраж — 00:00. Редакционные отметки не проставлены. Конкретные условия готовности в реализации определяет действующий серверный workflow.
- Синяя шапка остаётся над таблицей с названием, рубрикой и хронометражем. Сетка и действия со строками сохранены; одинаковые пустые строки не означают фиксированную высоту при реальном вводе. Исправлено двойное начертание нижней границы скопированных ячеек типов.

## Архив: R-006 и отображение по R-001/R-004

- Активна вкладка «Архив»; убраны очередь текущих действий и кнопка создания сюжета. Поиск и фильтр рубрики находятся в общей компактной строке.
- Шесть столбцов: название, рубрика, автор, исполнители, «В архиве с», действия. Приоритет и текущая стадия производства для завершённого сюжета не занимают место в этом варианте. Это предложение компоновки только архива, не сокращение активного списка.
- Автор — статичное имя без должности и выбора. В исполнителях показаны только монтажёр/дизайнер. Дата берётся из архивирования, не из последнего изменения. Четыре строки демонстрации, счётчик только под таблицей.
- В каждой строке две явные кнопки: **«Вернуть в работу»** и **«Удалить»**. Удаление спокойное текстовое с иконкой корзины; красная заливка используется только для окончательного подтверждения. Кнопки занимают одинаковые места во всех строках.
- Полный экран показан для руководителя без запрещающих функций. «Вернуть в работу» доступно только руководству. «Удалить» — всем активным сотрудникам без `video_editor`/`designer`, даже если они не авторы выбранного сюжета. При наличии этих функций удаление запрещено и начальнику/шефу. Поэтому роли обязаны фильтровать действия независимо, а не скрывать всю колонку по одному общему флагу.
- Поясняющий холст показывает просмотр для монтажёра/дизайнера без удаления и отдельно объясняет совмещение с руководством. Название сюжета остаётся ссылкой на карточку.

## Подтверждение и ошибка

- Заголовок **«Удалить сюжет навсегда?»**, точное название выбранного сюжета, понятные последствия для сценария и истории. Внешние файлы материалов по ссылкам сохраняются. Это отражает предложенный объём полного удаления из требований; точный серверный состав зависимостей ещё требует inventory.
- **«Отмена»** — спокойная кнопка, **«Удалить навсегда»** — красная. В рабочем приложении это модальный диалог над текущим архивом; начальный focus на отмене, Escape закрывает, focus возвращается на инициатор. Доступные имена связывают заголовок/описание диалога.
- После подтверждения блокировать повторное нажатие, показывать ход запроса. Не удалять строку из списка до подтверждённого успеха. Pending-состояние кнопки отдельно не нарисовано.
- При сетевой ошибке: **«Не удалось удалить сюжет. Сюжет остался в архиве. Можно повторить попытку»** и **«Повторить»**. Нижняя полоса на поясняющем холсте — альтернативное состояние ошибки, а не сообщение, одновременно открытое с первым подтверждением. Не использовать эту копию для ошибок «уже удалён», «восстановлен в работу» или «нет прав»: они требуют точного сообщения по ответу сервера.
- Восстановление и удаление остаются разными действиями. Сервер повторно проверяет права/архив при подтверждении; UI не обходит ограничения.

## Проверка и ограничения

Визуально проверены все три финальных снимка: общее выравнивание, ширины столбцов/слоты кнопок, переносы, читаемость, синяя шапка, четыре стартовых блока и четыре строки архива. Полный сценарий выше 768 px: макет показывает страницу с прокруткой, не обещает вместить всё в один экран. Реальная sticky-геометрия и работа при 1920 px/200% ещё не проверены.

Это статический Paper, не функциональная проверка Tiptap, шрифтов, сохранения, удаления или прав. При реализации использовать существующий редактор и механизм lease, сохранять пользовательское форматирование. MUI оформляет окружающие элементы в выбранной системе; библиотека не устанавливалась, её API этой итерацией не проверялось. Перед кодом нужен общий согласованный file-level план.

Утверждённые baseline-каталоги и ZIP не перезаписывались. Новые холсты созданы в копиях. Снимки сохранены из уже полученных результатов Paper; точный JSX новых макетов ещё не экспортирован. Получить его перед внедрением после согласования, не вычислять стили по скриншотам.

За итерацию **52 вызова Paper MCP**, включая проверки и завершение; 3 запроса добавления содержимого были отклонены инструментом из-за того, что пустой HTML-контейнер стал Rectangle. Он точечно заменён на Frame с заголовком, диалог проверен повторно. Не создавать пустые контейнеры для последующего наполнения в этом инструменте: сразу добавлять первый реальный дочерний элемент. Текущая квота аккаунта неизвестна, исторические расчёты не считаются текущим остатком.
