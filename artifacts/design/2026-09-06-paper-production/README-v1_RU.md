## Компоновка

1. Общая шапка скопирована с утверждённого экрана «Сюжеты» и сохраняет ширину основного содержимого.
2. Название, рубрика, автор, приоритет и ситуация объединены в компактный контекст сюжета. Главное действие справа, дополнительные — в меню. Отдельная карточка «Действия» убрана.
3. Три вкладки сохраняются: «Сценарий», «Производство», «История».
4. Озвучка, монтаж и титры представлены общей горизонтальной полосой. Это независимые направления работы, а не обязательная последовательность из трёх шагов.
5. Слева — пакеты правок и внешнее согласование. Справа — компактные назначения и материалы. Назначения сохраняют явные действия «Сохранить» и «Снять».
6. Вместо постоянно открытой формы добавления материала предложена кнопка «Добавить», раскрывающая форму по запросу. Конкретное раскрытие требуется проработать при реализации.

## Соответствие продуктовой модели

Все имена, сюжет и ссылки синтетические. Адреса используют зарезервированный домен example.invalid.

Показано состояние: озвучка не готова, монтаж в работе, титры ожидают редакционную готовность, корректуру и допуск ролика. Кнопка «Озвучка готова» соответствует первому доступному действию текущей серверной политики для этого примера. Менять порядок серверных действий только ради макета не предлагается.

Открыт один внутренний пакет с текстовой частью, назначенной автору. У руководителя нет кнопки завершения чужой части. Материалы остаются ссылками; озвучка остаётся отметкой готовности, без выдуманных файлов или отдельного исполнителя озвучки.

При реализации необходимо сохранить сворачивание завершённых этапов, скрытие недоступных действий, существующие подтверждения, права, параметры перехода production_context и отметку изменения сценария. Макет показывает один пример состояния, а не все роли и ситуации. Внешнее согласование сохраняет текущий ручной workflow.

## MUI

MUI MCP использован для чтения документации. TextField и Accordion получены через fetchDocs; для Button MCP вернул ошибку загрузки, страница проверена отдельно через официальный сайт.

Предлагаемое соответствие: Button contained для главного действия, outlined для вторичного и text для спокойных действий; TextField в режиме select для назначений; Accordion для завершённых этапов. Это ориентиры для будущей реализации, а не работающие React-компоненты внутри Paper.

Источники:
- https://mui.com/material-ui/react-button/
- https://mui.com/material-ui/react-text-field/
- https://mui.com/material-ui/react-accordion/

MUI не установлен во frontend. Автоматической двусторонней синхронизации Paper и кода нет. Перед реализацией требуется утверждённый file-level план по AGENTS.md, включая выбор версии библиотеки и проверку клавиатуры, состояний, длинного содержимого и разных размеров экрана.

## Проверки

Снимок Paper визуально проверен при 1366 × 768: показанные блоки помещаются, видимых обрезаний нет. Это проверка статического макета, не интерактивности.

В существующем приложении выполнен browser-тест `ux-hard-gate.spec.ts`, фильтр `story card preserves`, проект `chromium-1366`: 1 passed. Проверены три вкладки, сохранение URL после reload, одно главное действие, сворачивание завершённых этапов и отсутствие горизонтального переполнения. Тест проверяет исходное приложение, не новый макет. Старый CP7-снимок восстановлен после сохранения свежего снимка в этот каталог.
