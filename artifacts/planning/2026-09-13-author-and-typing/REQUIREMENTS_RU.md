# Список сюжетов и редактор — требования к доработкам

Дата: 2026-09-13. Источник: пожелания Павла в общем чате дизайна и технических доработок.
Статус: пожелания записаны; техническое решение и file-level план подготовлены для согласования. Реализация не начата.

## R-001. Автор в главном списке

В колонке «Автор» всегда обычный текст, одинаково для руководства и остальных сотрудников. Нет select, кнопки, ссылки, стрелки, должности и действий по нажатию. Значение — существующий `display_name`; при пустом имени — `username`. Не менять колонку исполнителей, быстрый приоритет, выбор автора при создании сюжета или серверные права.

В текущем коде select появляется только при наличии `story.management` и `onAuthorChange`; подпись select включает должность. В архиве используется тот же StoriesTable, уже без обработчика смены автора.

Павел подтвердил: сохранить смену автора **начальником и шеф-редактором** внутри карточки сюжета, в общем действии «Изменить». Серверный LEADERSHIP_FUNCTION_CODES уже содержит chief и chief_editor; обе роли обязательно покрыть тестами. Права не определяются отображаемым названием должности. Сейчас StoryHeader только отображает данные, готового альтернативного места смены автора нет. Поэтому удаление select нельзя ошибочно представить как перенос уже существующей функции: новый контроль в карточке — зависимость общего плана дизайна. Перенос в карточку и удаление select из списка выпускаются одним checkpoint: возможность смены автора не должна исчезать между обновлениями.

## R-002. Среднее тире

Павел явно выбрал `–`, U+2013 EN DASH. Символ дополнительно проверен в CaptionPanels:
- `/Volumes/work/Projects/CaptionPanels`, ветка main, HEAD aed26fa (проверено 2026-09-13);
- `cep_src/jsx/lib/utils.jsx:70` — общая `fixTypographyText`;
- строки 91–100: spaced hyphen, `--` и набор других тире нормализуются в `–`;
- `cep_src/jsx/lib/subtitles.jsx:107` — применение к тексту субтитров;
- `cep_src/jsx/lib/cleanup.jsx` — вызовы общей функции очистки.

Комментарий CaptionPanels местами называет знак «длинным», но фактический литерал — U+2013. Unicode-код важнее разговорного названия. CaptionPanels не изменялся; состояние установленного расширения не проверялось.

Предлагаемые клавиши в текстовых полях сценария:

| Ввод | Результат |
|---|---|
| NumpadSubtract без модификаторов | `–` U+2013 |
| Alt + основная клавиша минуса; Option + минус на Mac | `–` U+2013 |
| Основной минус без модификаторов | штатный `-` U+002D |
| Shift + основной минус | штатный символ раскладки, например `_` |

Сочетание Alt/Option + минус — рекомендация, требует согласования и проверки на реальных RU/EN раскладках macOS и Windows. Не использовать Ctrl/Cmd + минус, занятый масштабом браузера. Не перехватывать AltGr, Ctrl, Meta, composition/IME или неизвестный физический code. Удержание клавиши работает как обычный повторный ввод.

Область: основной текст, гео, ФИО, должность, «В кадре». Не имена файлов, TC, синяя шапка, поиск/замена, формы входа или другие input. Ввод заменяет выделение как обычный символ, не добавляет пробелов и не нормализует весь документ. Массовую обработку CaptionPanels и автозамену `--` в редактор не переносить.

Связанная правка: `russianQuotes.ts` сегодня считает U+2014 контекстом открывающей кавычки. Добавить U+2013, сохранив U+2014, чтобы после нового тире открывалась пара `«»`.

## R-003. Ёлочки и прямые кавычки

Сейчас RussianQuotesExtension перехватывает любой непосредственно введённый символ `"`. Источник клавиши не учитывается. Paste уже сохраняется без преобразования.

Предлагаемый контракт:

| Реальный ввод | Поведение |
|---|---|
| Shift + 2, если раскладка выдаёт `"` (обычная RU) | нынешние умные `«»`: пара, оборачивание выделения, переход за существующую закрывающую |
| Физическая Quote возле Enter, если она выдаёт `"` (обычная EN: Shift + Quote) | ровно один прямой символ `"` U+0022 |
| Quote, выдающая апостроф `'` | штатный апостроф |
| Та же физическая клавиша в RU, выдающая `э`/`Э` | штатная буква |
| Shift + 2 в EN, выдающий `@` | штатный `@` |
| Прямая кавычка из источника без физического code | сохранить нынешнюю умную обработку; не угадывать раскладку |
| Paste, загрузка документа, программная вставка | без новой автоматической замены |

Не заставлять клавишу возле Enter печатать кавычку вместо `Э`: это сломало бы русский текст. Не вводить глобальную слежку за раскладкой или предыдущей клавишей. Прямой ввод при выделении заменяет его одной кавычкой; только умные кавычки оборачивают выделение.

Одна операция — одна транзакция и одно обновление editor-core, форматирование сохраняется. Действующая общая история сценария получает изменение обычным путём; встроенную отдельную Tiptap history не включать. Фокус, выделение и прокрутка не должны прыгать после сохранения.

## R-004. Только монтажёр и дизайнер в колонке исполнителей

В главном списке показывать только назначения с каноническими kind `video_editor` и `designer`, в порядке монтажёр → дизайнер. Не включать `proofreader` и не считать корректора в кратком количестве. Не удалять само назначение корректора: оно остаётся в «Производстве», workflow и API.

Два назначения: «Монтажёр: Вега · Дизайнер: Орион». Одно — показать его; ни одного — прежнее «Не назначены». Если один человек выполняет обе роли, сохранить обе подписи ролей. Имена берутся из display_name (fallback username), а подписи ролей — из kind, а не из свободного поля должности. Просьба убрать должность у автора не переносится автоматически на названия ролей в этой колонке.

Сейчас `assigneeSummary` в StoriesTable учитывает все assignments и при числе больше двух показывает «Исполнителей: N». Вариант с корректором скрывает нужные имена. Фильтрация должна выполняться до форматирования и подсчётов; брать первые два произвольных назначения нельзя. При корректной модели по одному назначению каждого kind отображается максимум две роли. Общий компонент используется и в архиве; применить одинаковое отображение к обоим спискам.

Тестовая fixture StoriesTable.test.tsx содержит старый kind `video`, тогда как действующий контракт ASSIGNMENT_KINDS использует `video_editor`. Исправить fixture, не добавлять runtime-fallback для несуществующего legacy-kind.

## R-005. GEO по умолчанию жирным курсивом

Пожелание: строка GEO в ЗК+гео по умолчанию жирная курсивная. Последнее явное уточнение Павла: «Гео, гео жирный курсив». По фактическому коду сегодня default — `bold=false`, `italic=true`, то есть курсив, не подчёркивание. Проверено в `defaultScenarioFormatting` (frontend/src/features/scenario/scenarioTableModel.ts) и `_default_target_style` (backend/app/services/scenario_docx_renderer.py).

Новый default для пары `block_type=zk_geo`, `target=geo`: `bold=true`, `italic=true`. Остальной текст ЗК+гео сохраняет прежнее форматирование. Defaults Лайф и СНХ не менять. Не добавлять CSS !important и не делать GEO неизменно жирным: пользователь может изменить оформление вручную.

Явные сохранённые overrides `formatting.targets.geo` и rich-text marks имеют прежний приоритет, их не переписывать. Для строк без явного formatting используется новый default, в том числе при отображении уже сохранённой строки без override; отдельной миграции или массового изменения контента нет. Проверить новый блок, смену типа на ЗК+гео, reload и DOCX. Шрифт, синяя шапка, остальные столбцы и содержимое GEO не меняются. Не переносить CSS/жирность в текст JSON CaptionPanels и не менять его данные.

## Связь с утверждённым дизайном

Визуальные эталоны от 6 сентября неизменны и остаются снимком согласования. R-001 уточняет поведение колонки автора поверх старого требования сохранять её редактирование; не переписывать manifests или ZIP задним числом. Новое поведение реализовать при внедрении «Сюжетов», а отдельный интерфейс смены автора согласовать с общей шапкой карточки.

R-004 относится к тому же внедрению списка «Сюжеты». R-005 — синхронная корректировка defaults editor/DOCX.

R-002/R-003 — работа внутри существующего Tiptap editor-core. Не требуют MUI, изменений API, схемы данных или Paper-вызовов. Синяя шапка таблицы обязательна; сама таблица, блоки, TC и CaptionPanels-контракт сохраняются.
