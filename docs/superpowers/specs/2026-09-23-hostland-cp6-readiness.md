## Последовательность CP6 после отдельной команды владельца

1. Согласовать и выполнить снижение TTL обеих A-записей, например до 300 s,
   без изменения IP. Дождаться 86400 s после подтверждения на обоих NS;
   затем назначить окно переноса. Если ждать нельзя, оставить домашний вход
   без записи не менее суток и считать длительную ошибку для старого DNS
   явным риском.
2. Перед окном заново сверить точный SHA релиза, сертификат, свободное место,
   здоровье обоих серверов и уже доставленную домой проверенную полную копию.
   Зафиксировать время остановки записи. Закрыть домашний gateway для записи,
   сохранив старую БД и весь домашний runtime для восстановления.
3. На домашнем сервере создать новую зашифрованную полную точку после freeze,
   проверить хеш/расшифровку локально. Снять финальный `pg_dump -Fc`, сохранить
   ciphertext дома, сверить fingerprint до/после дампа. Передать только
   plaintext staging по pinned SSH в root-only каталог VDS; age identity
   остаётся дома. Восстановить в новый пустой production volume, сверить все
   21 таблицу до миграции и Alembic после. Удалить plaintext staging.
4. Запустить VDS на loopback в maintenance, затем провести закрытый HTTPS
   smoke с разрешённым тестовым автором. Создать новый зашифрованный полный
   комплект уже восстановленного VDS и убедиться, что он доставлен и
   проверен дома до открытия сайта.
5. Привязать gateway к 80/443 с maintenance, проверить TLS, заголовки и
   маршруты извне по прямому IP/`--resolve`. Только затем открыть приложение,
   изменить A-записи `@` и `www`, проверить оба NS, внешний браузер, вход,
   сохранение и установленный CaptionPanels. Старый домашний gateway не
   принимает запись в течение срока кэширования DNS.
6. После первых записей на VDS откат DNS на старую домашнюю БД запрещён без
   переноса новых записей. При сбое до первых записей можно вернуть прежний
   маршрут и домашний gateway после проверки целостности. CP7 включает
   подтверждение регулярной доставки DB points домой, restore первой новой
   копии, Certbot renewal и мониторинг.

## Наблюдение

`journald` хранит ошибки, но не уведомляет человека. Выбранный пока режим
«только журнал» означает, что сбой ночью обнаружится лишь при следующей
ручной проверке. Предложение для окна переноса: исполнитель проверяет сайт,
журналы VDS и возраст последней **доставленной домой** копии сразу после
переключения, через 15 минут, через 1 час и через 4 часа; ответственный
проверяет их утром, днём и вечером в первые двое суток, затем ежедневно.
Это ручной компромисс; для рабочего сервиса лучше добавить автоматическое
уведомление в Telegram или email о недоступности и просроченной копии.
Получатель и график пока не утверждены. Автоудаление старых копий выключено;
контакт ACME и вторая защищённая копия recovery key остаются открытыми.
