# Hostland: первичное обследование перед переездом

Дата проверки: 20 сентября 2026 года, около 18:49 UTC.
Статус: домашняя площадка обследована частично; ключ VDS подтверждён
владельцем через консоль, вход ожидает организации аутентификации. Это исходные наблюдения для
file-level плана, а не отчёт о завершённом переносе.

## Граница действий

Владелец разрешил начать подготовку и предоставил параметры SSH VDS.
Выполнены только чтение локальных настроек доступа, SSH-команды обследования
домашней площадки, получение публичного SSH-ключа VDS и DNS-запросы.
Приложение, серверные настройки, DNS, данные и расписания не изменялись.
Новые backup не создавались. Production env, пароли, приватные ключи,
содержимое сюжетов и файлы backup не читались и не выводились.

## HTTPS и DNS

- Рабочий gateway опубликован на LAN-интерфейсе домашнего сервера, порт 8088.
- Внешние 80/443 занимает отдельный edge-контейнер прежнего Compose project.
  HTTPS нельзя считать частью четырёх основных контейнеров нового runtime.
- Также обнаружен старый nginx-контейнер без опубликованных внешних портов.
  Его назначение и необходимость пока не подтверждены; удаление не выполнялось.
- Публичный DNS-ответ указывает NS `ns1.reg.ru` и `ns2.reg.ru`.
- A-запись соответствует домашнему внешнему адресу. Наблюдавшийся TTL около
  21600 секунд (6 часов). Доступ владельца к управлению DNS не проверен.
- Первый запрос AAAA не дал записей. Авторитетное отсутствие AAAA и политика
  CAA ещё не подтверждены: дополнительные запросы дали mismatch/timeout.
  Зависшую локальную DNS-проверку остановили; macOS dig завершился с внутренней
  ошибкой. Это ограничение проверки, а не доказательство неисправности DNS.

## Домашние резервные копии

- В ранее известном каталоге приложения найдена одна dump-копия.
- Размер dump: 285027 bytes; весь найденный каталог около 292 KiB.
- Проверялись метаданные файлов; содержимое, валидность checksum и
  восстанавливаемость этой копии в данном обследовании не проверялись.
- Права dump `0664`, backup-каталога `0775`, но родительский приватный каталог
  имеет `0700`, а домашний каталог пользователя — `0750`.
- Широкие биты самого файла не доказывают доступность другим пользователям:
  закрытый родительский каталог ограничивает проход. Полный ACL-аудит не
  проводился. Для нового механизма планируются явные ограниченные права
  и на каталог, и на каждый файл.
- У прикладного SSH-пользователя crontab не найден; среди видимых системных
  timers backup приложения не найден. Это не исключает root cron, задачи
  другого пользователя или внешнее резервирование.
- Свободного места для текущего объёма достаточно. Выбор выделенного каталога,
  владельца, шифрования, сроков хранения и мониторинга требует точного плана.

## VDS

Адрес, root-login и порт 22 предоставлены владельцем. В локальном known_hosts
для стандартного адреса VDS подтверждённый ключ не найден.

Публичный ED25519 ключ, полученный по сети и независимо подтверждённый
владельцем через консоль Hostland:

`SHA256:PZUa8qLnBx64kgFmDeIzEXDAOn+OYjvSQ7R2FV0KqsI`

Статус ключа: отпечаток совпал с результатом, предоставленным владельцем
из консоли Hostland. Повторный keyscan совпал с подтверждённым значением.
Ключ сохранён только во временный файл known_hosts для строгой проверки
этого подключения; постоянный known_hosts не изменялся.
Команда независимой проверки в консоли:

```sh
ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub
```

Пробный SSH-вход существующим ключом проекта при StrictHostKeyChecking=yes
отклонён сервером (publickey,password). У владельца запрошен ввод пароля
непосредственно в локальном Терминале для временного SSH master-соединения.
Новый публичный ключ на VDS не устанавливался. Control socket размещён
в отдельном локальном каталоге с правами 0700; после обследования соединение
нужно закрыть. Пароль не проходит через сообщения или аргументы команды.

Пароль и VNC-токен не сохраняются в этом документе. Аутентифицированных
команд на VDS пока не выполнялось; Ubuntu 26 / 2 CPU / 4 GB / 30 GB остаются
данными карточки провайдера, а не результатом обследования ОС.

## Выводы для дальнейшего плана

1. Объём текущей БД невелик. При отсутствии пользователей обычный dump/restore
   остаётся предпочтительным способом переноса; репликация ради простоя
   не требуется. Время переноса подтверждается репетицией.
2. Домашний сервер доступен по существующему ключу и имеет запас диска;
   повторно запрашивать его SSH-пароль не требуется.
3. Новый VDS должен иметь собственный HTTPS и не зависеть от старого edge.
4. Текущие backup-наблюдения не подтверждают регулярное полное резервирование;
   новый механизм и restore drill обязательны до допуска команды.
5. Низкое текущее потребление RAM контейнерами отражает простой приложения,
   а не доказанную вместимость для будущей нагрузки.
6. Ключ VDS проверен; нужно организовать безопасный первый вход,
   обследовать ОС и сеть, затем завершить file-level план.
7. Позднее нужны доступ владельца к DNS и выбор домашнего backup-каталога;
   эти сведения не мешают текущему обследованию VDS.
