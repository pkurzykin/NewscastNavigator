  Метки revision обоих образов указывают на exact SHA. PostgreSQL и gateway

  login/save/DOCX/CaptionPanels Origin:null. Production gateway template

  `full-20260923T140428Z-synthetic.tar.age`, SHA-256
  `b8dc66d942e0859fb30ea9596a22954786f41f595fa28509eb692c5f0144a887`,
  219466232 bytes, доставлен и проверен дома. Отдельная DB point

- Первая пробная full point была неполной (без gateway template). Её метаданные

  Исправлены упаковка и проверка цепочки, включая случай, когда вложенный SSH
  потреблял stdin и домашний pull пропускал DB point.
- Финальная версия упаковки включает recovery scripts: новая synthetic full
  `full-20260923T144043Z-synthetic.tar.age` (SHA-256
  `4f5962c1e11fa41ea1938020ad31c91a484b1eb70707399688fcb15ba55fe244`)

  `a52bd740ce8f4bb206828efe00f8d5da65886d521df8b035987a00e6565c8f99`)
  доставлены домой. Домашняя проверка состава/scripts и цепочки прошла;
  возраст последнего доставленного DB point при проверке — 72 s.
- После reboot VDS оба синтетических стека стартовали без сборки; входящие
  80/443/5432/8000/8090/8445 извне закрыты. Тест свежести обнаружил
  просроченную точку, затем прошёл после новой доставки. Systemd units прошли
  разбор `systemd-analyze verify`; предупреждения о ненайденных ExecStart
  ожидаемы, так как production каталог и службы ещё не установлены.
- Финальный production Compose/manifest проверен в отдельном root-only каталоге:
  `RELEASE_VERIFIED=true`. Шаблон gateway с новой схемой атомарного переключения
  пары TLS прошёл `nginx -t` и функциональную loopback-проверку: известный Host
  и HTTPS health — `200`, неизвестный Host — соединение закрыто (`444`).
  Production service при этом не запускался.
- Независимое ревью обнаружило и исправило повторную проверку старых домашних
  архивов: каждый частый pull пересчитывает SHA-256 актуальной DB-точки и
  соответствующего full bundle; отдельный `--scrub-all` проверяет всю историю,
  не создавая растущую нагрузку каждые две минуты. После обновления домашнего
  скрипта полный scrub шести точек и обычный pull прошли, новая точка
  `db-20260923T144945Z-synthetic.dump.age` доставлена за 15 s.
  Dry-run retention смотрит в `snapshots`, `DELETED=0`; таймер удаления отсутствует.
- Для будущего production full bundle закреплён воспроизводимый runtime:
  сертификат и ключ находятся вместе в `tls/versions/initial`, атомарный
  `tls/active` указывает на эту пару; в комплекте лежат service units,
  recovery scripts и runbook. На VDS проверен шаблон такого каталога, а
  домашний verifier допускает только относительную безопасную ссылку.

## CP5 — копия настоящей рабочей базы

- **До переноса** на домашнем сервере создана и проверена полная зашифрованная
  точка `precp5-20260923T142340Z-1.2.0.tar.age`, SHA-256
  `2d9e9941be71b7217ebac6739d000ba54e7b4dbb7a62c485f49fbfc08dd7ad82`,
  219855448 bytes. В неё входят БД, четыре образа, исходники старого релиза,
  конфигурация и TLS. Age identity не покидал домашний сервер.
- Дамп передан по pinned SSH в root-only закрытый клон VDS. При старой схеме
  `20260806_0004` **все 21 таблица** совпали с домашним источником по числу
  строк и содержимому (агрегированные хеши; реальные строки не выводились).
  Повторное восстановление в заполненную БД отклонено.
- Миграция на `20260914_0005` заняла 2977 ms. Числа строк всех 21 таблиц
  сохранились, хеши 17 неизменяемых таблиц совпали; значения нового шрифта
  соответствуют `PT Sans`. В отдельном клоне созданы только временный
  тестовый аккаунт и синтетические сюжеты. HTTPS login/save/reload,
  DOCX и CaptionPanels Origin:null прошли. Четыре контейнера healthy.
- `pg_dump -Fc` уже обновлённой копии занял 390 ms (один замер без
  параллельной нагрузки); свободно на VDS после теста ≈18.8 GiB. Снимок
  `docker stats` в покое: backend 87 MiB, DB 67 MiB, frontend 3 MiB,
  gateway 4 MiB. Это **не** пик под нагрузкой и не гарантия RPO/RTO.
  Перенесённый plaintext dump и пароль тестового пользователя удалены с VDS.
  Все контейнеры закрытого клона остановлены, его том пока сохранён.
  Домашний сервис остаётся healthy.

## До CP6

Нужны отдельная команда на остановку записи/DNS/открытие портов, выбор
финального точного релиза, график проверки журнала, контакт для ACME,
политика хранения и защита второй копии recovery key. На CP6 потребуется
**новая** полная точка после остановки записи: CP5 snapshot не заменяет
финальный dump. Production service/timers/Certbot сейчас не активированы;
публичного работающего 1.3.0 пока нет. Успешная репетиция не равна проверке
реального браузера и установленного CaptionPanels после переключения.
