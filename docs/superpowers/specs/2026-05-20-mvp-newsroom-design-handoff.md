## 3. Принятые Product Решения

Ключевые решения:

- главный объект — единая карточка от исходников до `Сдано`;
- финал workflow — `Сдано`, а не обязательно эфир;
- еженедельный выпуск новостей — опциональная группировка;
- общий активный реестр — стартовый экран;
- архив отдельно;
- `Сдано` остается активным до ручного архивирования;
- создать карточку может любой рабочий пользователь;
- исходники требуют только дату, название и путь;
- сюжет требует рубрику;
- рубрику можно менять;
- у сюжета есть роль-слоты: автор, корректор, монтажер, дизайнер титров;
- роль-слоты можно оставить пустыми;
- назначения меняют шеф, шеф-редактор, админ;
- владелец процесса ставится по умолчанию и может быть изменен;
- существующий текстовый редактор сохраняется;
- workspace draft и text state — разные сущности;
- autosave не создает workflow text state;
- text state создается явным workflow-действием;
- после проверки текста параллельно могут стартовать озвучка, вычитка, монтаж;
- озвучка — upload/download аудиофайла;
- остальные медиа — сетевые/локальные пути;
- монтаж готов только с финальной актуальной озвучкой;
- черновые титры возможны только по разрешению шефа/шеф-редактора;
- финальные титры после `Монтаж OK`;
- перед внешним согласованием есть два внутренних gate: монтаж OK и титры OK;
- внешнее согласование не интегрируется в систему, только ручная отметка;
- внешний `OK` автоматически переводит карточку в `Сдано`;
- внешние замечания — это замечания к ролику, а не к текстовому документу;
- если замечание меняет source text, это должно попасть в text state;
- быстрый путь возможен для мелких правок по монтажу, титрам и озвучке;
- титры при изменении текста всегда требуют перетитровки, без override.

## 4. Принятые UX/UI Решения

Зафиксированы low-fidelity решения:

### Главный Реестр

Принят вариант:

```text
desktop: активный реестр + правый предпросмотр;
narrow/mobile: список без предпросмотра + открытие карточки отдельным экраном.
```

Не использовать карточную доску как основной экран.

### Карточка

Принят подход:

```text
command layout + text-first
```

Карточка открывается как рабочее место сюжета, а не как dashboard из равных панелей.

Текст сюжета — главный содержательный объект карточки. При открытии карточки пользователь должен сразу видеть рабочую таблицу текста в карточке. Редактор нельзя прятать за кнопку `Открыть редактор`; отдельный focus/fullscreen-режим допустим только как дополнение.

### Текстовое Рабочее Место

Редактор занимает центральную и самую большую область.

Поддерживающие зоны:

- слева: контекст сюжета, исходники, команда;
- справа: workflow, замечания, отправка на проверку, предупреждения.

### Производство

Принят подход:

```text
compact track strip + production gates
```

Визуальная логика:

```text
озвучка готова
→ монтаж с озвучкой
→ проверка монтажа
→ титры
→ проверка титров
→ внешнее согласование
```

### Внешнее Согласование

Принят подход:

- ручная отметка `Отправлено на согласование`;
- история циклов;
- результат `OK` или замечания;
- замечание к ролику + внутренние последствия;
- без внешнего approval-кабинета.

### Создание Карточки

Принят подход:

```text
Создать карточку
→ Исходники / материал
→ Сюжет в работу
```

### Ролевые Представления

Один общий реестр, но разные фильтры, акценты и CTA для ролей.

Не делать отдельные приложения по ролям.

### Архив И Админка

- архив отдельно от активного реестра;
- админка отдельно от newsroom-flow;
- управление пользователями не показывать внутри карточки сюжета.

## 5. Visual Pass

Выбрано направление:

```text
Operational Service
```

Утвержденные key screens:

- главный реестр: плотный общий реестр + правый preview на desktop;
- карточка сюжета: command layout + text-first;
- текстовое рабочее место: редактируемая таблица текста видна сразу;
- производство/согласование: compact track strip + production gates;
- проверка монтажа: один вход в правки `Зафиксировать правки`;
- utility-действия по ролику не являются главным CTA;
- внешнее согласование: ручная отметка и результат, без approval-сервиса;
- создание карточки: один вход `Создать карточку`, затем стартовая стадия.

Еще не финализированы пиксельные детали:

- точная плотность таблиц;
- точные hover/focus states;
- финальные иконки;
- точная типографическая шкала;
- responsive polish;
- visual smoke на реальном frontend после реализации.

## 7. Guardrail Для Следующей Сессии

При написании implementation plan удерживать:

- не добавлять новый UI поверх старых конкурирующих экранов;
- главный реестр остается единым newsroom-реестром;
- `Моя работа` остается представлением/фильтром, не отдельной структурой;
- карточка не становится dashboard из равных блоков;
- текстовая таблица видна и редактируема сразу;
- editor-core не переписывать без отдельного плана;
- production строить вокруг gates, не вокруг стены статусов;
- внешнее согласование не превращать в approval-сервис.

Каждый PR должен отвечать:

```text
что переиспользуем?
что удаляем?
что перестраиваем?
как проверяем?
какой пользовательский сценарий стал понятнее?
```
