Статус: основа внедрения утверждена 14 сентября 2026 года; конкретные компоненты и проверки фиксируются по мере реализации.

## Основные правила

Тёплый светло-серый canvas `#F1F0EB`, белые рабочие поверхности, header `#F7F5EF`, синий action `#245F9E`, графитовый текст. Мягкие рамки и небольшие тени; без стекла, неона и тяжёлых градиентов. UI — Onest, шрифты содержимого сценария независимы.

На 1366 ширина основной области 1294, боковые поля 36. Общая шапка 56, отступ сверху 12, радиус 8. Края header/очереди/таблицы совпадают. На широких экранах сохраняется полезная рабочая ширина существующего приложения.

Один главный action в контексте. Вторичные действия имеют понятные подписи. Режим чтения оставляет текст контрастным; отсутствие прав не изображается формой редактирования. Ошибки показывают следующий шаг, фокус и локальные значения сохраняются.

Синяя шапка сценария `#BEDCE6` с названием, рубрикой, хронометражем обязательна. Пять колонок, блоки, TC/файлы, rich text и все операции сохраняются. MUI оформляет окружение; Data Grid не заменяет сценарную таблицу.

## Проверка

Chromium 1366×768, 1920×1080 и существующая проверка wide-layout. Длинные имена, названия и текст; empty/loading/error; клавиатура; aria/focus; чтение/сохранение/конфликт. Снимок не доказывает работу взаимодействий. Runtime проверить в браузере и тестами.

Все review выполняются Codex. CodeRabbit запрещён пользователем.

## Реализация и повторное использование

Источник визуальных значений — `frontend/src/styles/tokens.css`. MUI-тема
`frontend/src/shared/ui/theme.ts` читает эти же значения; независимую палитру
для отдельных страниц не заводим. `UiProvider` подключён один раз на входе
приложения. Глобального сброса типографики редактора нет.

| Элемент | Реализация | Правило использования |
|---|---|---|
| Кнопки | MUI Button / IconButton | Главное действие залито синим; вторичные — контур или текст; danger — красный. Без заглавных букв по умолчанию. Локальные variant-классы не используются. |
| Диалог | MUI Dialog | Название цели, явные действия; initial focus, focus trap, Escape и возврат фокуса обеспечивает общий компонент. Во время отправки исключается повтор. |
| Выбор исполнителя | MUI Autocomplete / AssignmentPicker | Автор первым, затем корректор, монтажёр, дизайнер. Поиск и стрелки не сохраняют. Явный выбор сохраняет; «Без исполнителя» снимает назначение, но автор обязателен. Права автора определяет management read model. |
| Поля входа и пароля | MUI TextField в auth-form | Native required/autocomplete/minLength сохраняются; карточка использует общие отступы и тень. |
| Сотрудники | AdminUsersManager, MUI Dialog / TextField / Checkbox / Alert | Существующие проверки и команды сохраняются; create-dialog помещает действия на 1366×768. |
| Уведомления | NotificationTray | Компактная всплывающая поверхность; ссылка на историю, явное прочтение, Escape и возврат фокуса. |
| Что нового | WhatsNewDialog с MUI Dialog / Button | Общий focus trap, блокировка клавиш редактора и отметка просмотра на пользователя/версию сохраняются. |
| Меню профиля | UserProfileMenu | Компактное имя/должность; пароль и выход доступны с клавиатуры. |
| Ошибка | MUI Alert или существующий inline status | Понятная причина и повтор; локальные значения сохраняются. После успешного ack повторяется GET, а не команда. |
| Шапка приложения | AppShell | Общие границы с рабочей областью, 56 px на desktop, умеренная тень. |
| Шапка карточки и вкладки | StoryHeader, StoryTabs | Название и контекст слева, доступные действия уровня сюжета справа; активная вкладка отмечена синим. Действия рабочих этапов находятся у их статусов. |
| Этапы производства | ProductionStages / ProductionActions, MUI Button | Три колонки на белой поверхности: статус слева, действия этапа рядом справа. Первичность задаёт сервер; перенос не создаёт новых прав или команд. |
| Рабочая поверхность | production-section / stories-table-wrap | Белая поверхность, мягкая рамка, небольшая тень. Связанные элементы сгруппированы отступами. |
| Таблица сценария | Существующие ScenarioEditor / ScenarioRow | Собственная типографика текста и обязательная синяя шапка; окружение подчиняется общей теме. |
| Доступ к сценарию | ScenarioEditor / EditLeaseNotice, MUI Switch | Чтение контрастное; редактирование начинается после своей lease. Ошибка сохраняет локальный ввод; повтор release не пересылает текст. |
| Основной шрифт | Панель «Шрифт сценария» | PT Sans / Franklin Gothic Book — настройка всего сценария; ручной «Основной (…)» снимает override. Остальные шесть гарнитур и B/I сохраняются. |
| Архивное удаление | ArchiveDeleteDialog | Название сюжета и явное подтверждение, фокус на отмене. Права по read model; после ack при ошибке обновления повторяется только чтение. |
| История | HistoryTimeline / ScenarioSessionDiff | Показать/скрыть, независимая загрузка сравнений. Красный del / зелёный ins с дополнительным начертанием; исходный текст и ручные стили сохраняются. |
| Восстановление | RestoreScenarioDialog | Ясное состояние на конец сеанса, отмена первой. Уже актуальный snapshot — нейтральное сообщение, без ложного успеха. |

Новые экраны используют эти элементы и токены. Новый локальный вариант добавляется
в общую тему или компонент, когда появляется подтверждённая потребность; копию
кнопки/диалога с отдельными цветами для очередной страницы не создаём.

Контракт закреплён автоматическим тестом
`frontend/src/shared/ui/uiSystemContract.test.ts`. В runtime-коде запрещены
самодельные `dialog`, generic-классы `.primary/.secondary/.danger/.text-button`,
цветовые литералы вне `tokens.css` и обычные native controls вне явно
перечисленных частей сценарной таблицы. Исключение охватывает только ввод
содержимого, Tiptap, drag/resize и lease-поля; окружающие кнопки, поиск,
переключатели, статусы и подтверждения используют MUI.

## Текущий результат и дальнейшее развитие

Тема, токены и перечисленные компоненты внедрены в действующие экраны.
Они составляют дизайн-систему проекта; отдельной второй реализации интерфейса
и копии сценарного редактора нет. Каталог выше — документация фактических
компонентов, не отдельное приложение Storybook.

Список, производство, формы, уведомления, доступ, архив и История проверены
на 1366/1920; общая геометрия — также на 2560. Тестируются pending/error,
клавиатура и возврат фокуса, локальный ввод и восстановление после ошибок.
Результаты и оставшиеся platform gates: `../product-reset/UX_EVAL_RU.md` и
`../product-reset/PROGRESS.md`. Общий обзор ветки фиксируется в handoff.

15 сентября пользователь уточнил цель: реализовать именно локальный вариант
14 сентября и проверить весь фронтенд на смешение старых и новых правил.
Целевой редактор: тонкие серые разделители, прямоугольные компактные элементы,
раздельные IN/OUT, два переключателя основного шрифта, синяя шапка и все
существующие функции. Демонстрационная логика макета не переносится.
Главный акцент задаётся явным MUI `variant="contained"`; остальные действия
используют `outlined` или `text`. Стили компонентов определяются общей темой,
а feature CSS отвечает за раскладку и содержимое.

## Принятая доводка 20 сентября 2026

Формы правок и уведомления приняты пользователем по сохранённым макетам
`artifacts/design/2026-09-20-paper-corrections-notifications/`. Внедрение
разрешено без дополнительных вызовов Paper; макеты используют Onest и
существующую палитру. Лимит Paper не проверяется дополнительным запросом.

- Форма правок: ширина около 633 px, область и исполнитель в верхнем ряду,
  описание на всю ширину. Внутренние правки содержат одну часть без лишней
  рамки «Часть 1»; внешние сохраняют нумерацию, добавление и удаление частей.
  Заголовок и действия остаются доступны при прокрутке длинной формы.
  Общие поля и кнопки переиспользуются, ошибка не стирает заполненный текст.
- Уведомления: панель 460 px, компактные строки с индикатором непрочитанного,
  событием, сюжетом и доступными данными автора/времени. Полезное содержание
  уведомления сохраняется. Отметка прочтения — отдельная подписанная кнопка,
  ссылка сама не отправляет команду прочтения. Сохраняется правило SPEC (§11/§18):
  уведомления монтажёру/дизайнеру об изменении сценария подтверждаются сервером
  после фактического открытия обновлённой редакции в соответствующем контексте.
  Сравнение раскрывается и сворачивается;
  текст, оформление и изменения пустых блоков имеют понятное объяснение.
- Очередь внимания: корректное склонение счётчика, перенос длинного контекста
  и действий, три пункта в компактном представлении. Описание занимает до трёх
  строк; полный текст остаётся в DOM и доступен при наведении. Даже правка
  на 2000 знаков не вытесняет таблицу за пределы первого экрана.
- Создание сюжета и рубрики: заголовок 20/28 px, подписи 13 px, поля 14 px,
  кнопки 32 px. В форме сюжета действия «Отмена → Создать» справа на тёплом фоне.
- История: короткие служебные события плотнее сеансов редактирования;
  раскрытые сравнения и операции восстановления сохраняют свой акцент.

Точные результаты внедрения и проверок фиксируются в
`../product-reset/UI_POLISH_2026_09_20_PLAN.md` и `../product-reset/PROGRESS.md`.


Кнопки добавления блоков сценария повторяют цвета типов колонки «Блок»:
Подводка `#475467`, ЗК `#1849a9`, ЗК+гео `#6941c6`, Лайф `#b54708`,
СНХ `#067647`. Одна CSS-переменная на тип задаёт цвет надписи обоих элементов;
у кнопки — мягкая заливка 9% и рамка 25% того же цвета поверх белой поверхности.


Материалы: HTTP(S)-адрес — подчёркнутая ссылка в отдельную вкладку с
`noopener noreferrer`. Локальный путь — обычный текст и «Копировать путь».
Для UNC/SMB показывается «Скопировать: Для Windows / Для Linux» (UNC / SMB URI).
Адрес сервера из локального диска не выводится. Парные внешние кавычки снимаются
только при отображении/копировании, сохранённое значение остаётся исходным.
Успех подтверждается после фактического копирования. При запрете обоих механизмов
копирования появляется выделенное read-only поле и подсказка Ctrl+C/⌘C.
Никаких дополнительных компонентов, прямого открытия файлов или изменений
настроек браузера для этого интерфейса не требуется.

## Автор и редакционные отметки — уточнение 20 сентября

В шапках сценария, производства и истории нет общей кнопки «Изменить». Автор остаётся
в подписи под названием; его выбор находится в первой строке «Исполнителей».
Для начальника/шефа — поиск и немедленное сохранение выбора, для остальных — имя.

Редакционные действия находятся над редактором рядом с соответствующей отметкой
запроса проверки, редакционной готовности или корректуры. Используются MUI Button
и общие токены. Для mark_proofread подпись «Отметить вычитанным»; после выполнения
статус «Вычитано», имя и время. Кнопки определяет server read model: вычитка
доступна назначенному корректору, начальнику и шефу. Старый portal в шапку,
native workflow buttons и конфликтующие CSS overrides удалены.

## Производственные действия у статусов — уточнение 20 сентября

Озвучка, монтаж и титры объединяют текущий статус и все доступные действия
своего этапа, включая запуск, готовность, приёмку и возврат на правки.
Допуск `video_approve_for_titles` находится в «Титрах» с подписью «Готово к титрам»:
он открывает следующий этап. «Ролик готов» и возврат ролика на правки относятся
к «Монтажу». Уточнение пользователя 21 сентября заменяет размещение допуска
по техническому префиксу `video_`; команда и условия допуска сохраняются.
Распределение по первым двум позициям списка отменено. В шапке остаются
действия уровня сюжета (эфир, архив, возврат в работу); действие без подходящего
этапа также остаётся доступным там. Каждая команда показана один раз.

Подпись «Готово к титрам» согласована в серверных действиях карточки и очереди
внимания. Серверные emphasis, method, href, confirmation и формы сохраняются.
Единственное главное действие остаётся выделенным даже внутри этапа.
Кнопки переносят длинные подписи; ошибки видны рядом с действием. Pending блокирует команды по всей
странице, после подтверждённой команды повтор обновления выполняет только GET.
Переход к следующему действию этапа не перехватывает фокус.

Правки сохраняют единое действие завершения внутри своей части пакета;
внешнее согласование — собственные действия и формы в блоке согласования.
Серверные gates и доступность для назначенных сотрудников и руководства
не меняются. Проверки и артефакты перечислены в `../product-reset/PROGRESS.md`.

Возврат озвучки использует общий `CorrectionPackageDialog`: «Новые правки»,
область и ответственный в верхнем ряду, описание на всю ширину, общие MUI-кнопки
и закреплённые действия. Область «Озвучка» фиксирована, поскольку команда
возвращает именно этот этап. Кнопка «Создать правку и вернуть» сохраняет понятный
результат; API получает прежние description и assignee_user_id. Встроенная
native-форма и её CSS удалены. Ошибка сохраняет текст и исполнителя, отмена
возвращает фокус, повтор после ack выполняет только чтение. Уточнение принято
по прямому запросу пользователя 21 сентября.

## Единый компонентный контракт — 21 сентября 2026

Все обычные интерактивные элементы приложения используют общую MUI-тему:
кнопки и иконки, поля, списки, флажки, переключатели, статусы, уведомления,
popover и модальные окна. Это правило распространяется на список сюжетов,
производство и правки, внешнее согласование, материалы, историю, сотрудников,
уведомления, release notes и панели сценария. Feature CSS задаёт раскладку и
содержательные особенности, а размеры, состояния, фокус, цвета и поверхности
принадлежат теме и семантическим токенам.

Runtime-тест `frontend/src/shared/ui/uiSystemContract.test.ts` рекурсивно
запрещает возвращать старые классы кнопок, собственные dialog-реализации,
нативные контролы обычных форм, локальные литералы цветов и имитацию общих
компонентов в `base.css`. Допустимые нативные элементы ограничены внутренними
полями табличного редактора сценария: Tiptap, изменение колонок, drag-and-drop
и `AccessNativeField`. Это сохранённая часть рабочего контракта редактора,
а не альтернативная дизайн-система.

Диалоги сохраняют введённые данные при ошибке, блокируют повторную команду,
удерживают действия и сообщение об ошибке в пределах viewport и возвращают
фокус на вызвавший элемент после Escape или отмены. Клик по фону формы
сотрудника не уничтожает незаписанный черновик. Popover уведомлений также
возвращает фокус после Escape. Эти свойства закреплены component-, browser-
и Axe-проверками на 1366×768 и 1920×1080.

Все подтверждения действий используют общий MUI `ConfirmationDialog`.
Runtime-вызовы `window.confirm`, `window.alert` и `window.prompt` запрещены
контрактным тестом вместе с собственными dialog-реализациями. Формы правок,
внешнего согласования и сотрудников не закрываются по клику на фон, поэтому
случайный клик не уничтожает черновик.

Плотные рабочие поверхности дополнительно задают локальную геометрию поверх
общей темы. В реестре сюжетов фильтры имеют высоту 36 px без отдельной тени,
а изменяемый приоритет — компактную капсулу 100×26 px. Текст и стрелка
центрируются независимо и не обрезаются; колонка приоритета занимает только
необходимую ширину. При переносе действий на следующую строку декоративный
разделитель убирается. Эти значения закреплены browser-проверками геометрии,
а не только снимками.

В сценарии нативные поля рабочего ядра явно владеют своими размерами и
типографикой. Фокус в текстовой ячейке использует нейтральную внутреннюю рамку,
семантические кнопки пяти типов блоков сохраняют свои цвета, а панель
инструментов на компактной ширине остаётся внутри страницы с локальной
горизонтальной прокруткой. В шапке значок, счётчик и подпись уведомлений
занимают отдельные выровненные места; сетка функций сотрудника сохраняет две
колонки на доступной ширине.

Подтверждение выхода из редактора также входит в общий визуальный контракт.
SPA хранит позицию каждой своей записи в `history.state`: отменённый Back
возвращает принятую запись через `history.go`, подтверждённый Back не добавляет
дубликат, а Forward во время открытого подтверждения инвалидирует устаревший
запрос. Нативный `beforeunload` остаётся только системной защитой браузера при
закрытии вкладки или полном уходе со страницы.
