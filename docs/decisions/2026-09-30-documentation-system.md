# Единая документация для людей и агентов

Тип: решение. Статус: принято. Ответственный: владелец проекта.
Проверено по источникам: 30 сентября 2026, исходный Git `09d4c52` и решение владельца.

## Решение

Владелец утвердил реорганизацию всей документации и поручил реализацию.
README вводит человека в проект; AGENTS задаёт агенту порядок работы и
границы полномочий. Оба используют одни действующие требования и инструкции.

Каталоги docs/product, guides, engineering и operations содержат текущие
требования, руководство редакции, разработку и эксплуатацию. Существенные
решения, активные планы и датированные отчёты находятся в decisions, plans,
reports. Завершённые планы и исследования хранятся в archive.

Текущее работающее состояние — исходная точка. Владелец подтвердил, что вопросы
прошлых этапов закрыты. Это решение о статусе не меняет измеренные результаты
исторических проверок и не выдаёт новую проверку сервиса за выполненную.

## Причины

Прежняя структура отражала названия этапов и инструментов, текущие инструкции
смешивались с историей, а большой журнал мешал быстро продолжать работу.
Одного нового оглавления недостаточно для исправления содержания. Отдельный
сайт документации добавил бы второй процесс публикации; Markdown в Git уже
доступен людям, агентам, ревью и автоматическим проверкам.

## Сопровождение

У каждого правила один основной документ. Изменение поведения, команды или
процесса включает обновление связанных документов. AGENTS, PR-шаблон,
проверки CI и шаблоны документов закрепляют это условие завершения задачи.
Автоматика проверяет структуру и ссылки; автор и ревьюер отвечают за смысл.

Короткое состояние проекта заменяет устаревшие сведения. Результаты каждой
задачи сохраняются отдельным отчётом; завершённый план закрывается и уходит
в архив. Новый мегажурнал не создаётся.

## Последствия и совместимость

Перенос меняет навигацию и doc-policy tests. Runtime и серверные команды
не меняются. Исторические machine-readable свидетельства и связанные с ними
документы сохраняются побайтно на исходных путях, поскольку evaluator
связывает их с прежними Git SHA и хешами. Архивный индекс описывает это
исключение; новые задачи не дописывают замороженный журнал.
