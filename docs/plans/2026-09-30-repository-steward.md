# Включение куратора репозитория в рабочий процесс

Владелец утвердил предложение в задаче: настроить роль и общий порядок,
затем опубликовать текущую ветку, создать PR, дождаться CI, выполнить merge
с сохранением коммитов, синхронизировать main и провести разрешённую очистку.
Начальный HEAD `90fd9902f7452c04e6047fd6f0b2c194635f4310`, ветка
`codex/documentation-system`; remote main `09d4c52f085f6961d88366b439408f8ba4dc3e45`.

## Область реализации

- Глобальные `~/.codex/AGENTS.md`, `agents/repository-steward.toml`,
  только модель/усилие по умолчанию в `config.toml`: sol/high и правила вызова.
- Проектные AGENTS, Git workflow, DEVELOPMENT, PROJECT_AGENTS, release workflow,
  documentation policy, PR/report templates, индексы и PROJECT_STATE.
- Read-only инвентаризация трёх прежних worktree; KEEP при неизвестной
  активности/данных. Мутации выполняются координатором по заключению куратора.
- GitHub main: PR, три обязательных CI, актуальный base, без force-push/deletion;
  без обязательного второго человека для проекта одного владельца.
- Runtime приложения, зависимости, секреты, рабочие БД и серверы вне задачи.

## Checkpoints реализации

- [ ] Настроить роль и непротиворечивый порядок завершения.
- [ ] Проверить документы/TOML, независимые review/verification одного снимка.
- [ ] Получить заключения кураторов, закрыть реализацию и передать кандидата в PR.

## Проверки и операционное завершение

TOML и точечный diff глобальных настроек; `python3 scripts/check_docs.py`,
unit checker, `git diff --check`; отдельные review и verification кандидата.
При публикации — CI текущего PR; после merge — CI main, достижимость SHA
`0cb6b13`, сверка local/origin/remote и clean status. Перед удалением worktree
проверяются активные задачи и ignored данные. Историю не переписывать.

Этот план описывает реализацию процесса и готовность кандидата. Итог внешних
шагов после merge фиксируется в связанном PR и ответе задачи; [отчёт](../reports/2026-09-30-repository-steward.md)
сохраняет снимок реализации. Невыполненные внешние этапы явно остаются PENDING
до свежей проверки. Tag/release/deploy и автоматическое расписание не входят
в утверждённый пакет.
