# NewscastNavigator 1.1.1 — визуальные исправления экспорта DOCX

Статус: утверждено владельцем продукта 14 августа 2026 года.

## 1. Цель и границы

Патч уточняет только отображение уже существующих данных в каноническом
DOCX-экспорте актуального сценария. API, база данных, snapshot-контракт,
редактор сценария, автосохранение и CaptionPanels не меняются.

Версия выпуска — `1.1.1`. Существующий тег `v1.1.0` не перемещается.

## 2. Утверждённый макет

### 2.1. Голубая шапка

Три первые голубые строки таблицы сохраняют текущую структуру:

1. общая ячейка с названием и рубрикой;
2. общая ячейка с хронометражем;
3. заголовки «Текст в титре», «В кадре», «Звук».

Этот блок присутствует только в начале первой страницы. Ни одна строка
таблицы не помечается `w:tblHeader`; на страницах продолжения отображаются
только рабочие строки.

### 2.2. Блок «Лайф»

Для строки типа `life` колонка «Текст в титре» содержит:

1. отдельный служебный абзац `Лайф` жирным курсивом;
2. основной текст блока с сохранением разрешённого run-level форматирования.

Колонки «В кадре» и «Звук» для текста `life` остаются пустыми, кроме обычных
file bundles и дополнительного комментария, если они отдельно присутствуют
в данных строки.

### 2.3. Геопривязка

Для строки `zk_geo` первый абзац начинается с буквального префикса `Гео: `,
после которого без переноса следует значение геопривязки. Форматирование
самого значения сохраняется. Основной текст блока остаётся следующим
абзацем.

### 2.4. Файлы и тайминги

В колонке «В кадре» последовательные bundles с одинаковым непустым, уже
нормализованным `file_name` образуют одну визуальную группу:

```text
<имя файла>
<первый диапазон>
+
<следующий диапазон>
```

- имя файла выводится один раз и жирным;
- тайминги и знак `+` выводятся обычным начертанием;
- знак `+` занимает отдельную строку между диапазонами;
- одинаковое имя объединяется только в непрерывной последовательности;
- другое имя начинает новую группу и не меняет исходный порядок;
- bundles без имени не склеиваются между собой;
- одиночный bundle, пустая граница диапазона и дополнительный комментарий
  сохраняют прежнее поведение.

Экспорт не добавляет слово `Файл` автоматически: отображается сохранённое имя.

## 3. Реализация

Изменение локализуется в `backend/app/services/scenario_docx_renderer.py`.
Существующий immutable `ScenarioDocxSnapshot` и публичный интерфейс
`render_scenario_docx(snapshot) -> BytesIO` сохраняются.

Небольшие внутренние helpers могут:

- добавлять служебный префикс перед первым абзацем, не теряя его runs;
- записывать одну визуальную группу последовательных file bundles;
- применять отдельный bold только к имени файла.

Runtime по-прежнему создаёт DOCX только в памяти и не пишет его на серверный
диск.

## 4. Проверка

Обязательны:

- RED/GREEN pytest для всех четырёх визуальных правил и edge cases;
- structural OOXML-проверка отсутствия `w:tblHeader`;
- синтетический документ на нескольких страницах;
- render через LibreOffice и просмотр каждой страницы в PNG;
- профильные и полные backend-тесты, frontend tests/build, DOCX Playwright,
  Compose config и `git diff --check`;
- committed-diff CodeRabbit и независимый whole-branch review;
- production backup, deploy exact SHA, authenticated DOCX/CaptionPanels smoke
  и проверка экспортированного production DOCX до создания тега `v1.1.1`.

Полный clean-deploy rehearsal не повторяется: миграции, зависимости, Docker,
Compose, deploy-, backup- и restore-контракты этим патчем не изменяются.

Production backup, deploy, smoke и создание/публикация тега выполняются только
после отдельной явной команды владельца продукта; существующий тег `v1.1.0`
не перемещается.
