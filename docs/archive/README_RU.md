# Отобранный архив проекта

Здесь остаются материалы с конкретным дальнейшим применением. Полный прежний
состав хранится в Git. Архив не назначает задач и не переносит разрешения
прошлых этапов. Текущие источники — в [каталоге документации](../README_RU.md).

## Что сохраняется в дереве

- [Сюжеты — визуальный эталон](2026-design/2026-09-06-paper-stories/approved-baseline/README_RU.md).
- [Производство — визуальный эталон](2026-design/2026-09-06-paper-production/approved-baseline/README_RU.md).
- [Сценарий — визуальный эталон](2026-design/2026-09-06-paper-scenario/approved-baseline/README_RU.md).
- [Закрытый план реорганизации](2026-documentation/2026-09-30-documentation-system.md) — основание действующей структуры и [итогового отчёта](../reports/2026-09-30-documentation-system.md).

Эталоны сохраняют утверждённые PNG и исходные экспорты для сравнения при
изменении UI. Это статические исторические материалы; текущие права,
компоненты и поведение задаются продуктовой спецификацией и дизайн-системой.
Манифест каждого эталона проверяет только tracked файлы, их размеры и SHA-256.

## Технические исторические доказательства

[Манифест доказательств](EVIDENCE_MANIFEST.json) сохраняет хеши девяти исходных
файлов. Для шести файлов проверяются Git blobs точного снимка
`09d4c52f085f6961d88366b439408f8ba4dc3e45`; копии в текущем дереве не нужны.
Это PROGRESS, RISK_REGISTER, ARCHITECTURE_INVENTORY, OPERATIONS_INVENTORY,
LEGACY_DENYLIST и EVAL_COMMANDS. Проверки их содержания продолжают работать.

Три входа существующего evaluator остаются на его канонических путях:

- [EVAL_RESULT.json](../product-reset/EVAL_RESULT.json);
- [DEMO_EVIDENCE.json](../product-reset/DEMO_EVIDENCE.json);
- [UX_EVAL_RU.md](../product-reset/UX_EVAL_RU.md).

Они привязаны к прежним Git SHA и не являются текущими инструкциями.
Внутренние ссылки UX-оценки описывают исходный checkout; 11 ссылок на 9 локальных
PNG прежнего UI-прогона не обещаются в Git-клоне. Новые снимки не подменяют
исторические доказательства. Новые записи в старый журнал не добавляются.

## Найти удалённый материал

[Карта второго прохода](../reports/2026-09-30-documentation-cleanup-map.json)
перечисляет удалённые пути, причины и хеши исходного содержимого. Базовый
снимок перед очисткой — `0cb6b13fb8ca02fdc4c1304b1a5f080fad8b9569`.
Например, прочитать прежний план без возвращения его в рабочий каталог:

```bash
git show 0cb6b13fb8ca02fdc4c1304b1a5f080fad8b9569:docs/archive/2026-product-rebuild/IMPLEMENTATION_PLAN_RU.md
```

Для получения группы файлов используйте `git archive <SHA> <path>` с указанным
снимком и путём; экспорт выполняйте в отдельный каталог. Для этого нужна
Git-история с соответствующим commit. Проверки CI используют полный checkout.
Архив исходников без `.git` сам по себе не содержит исторические Git blobs.

[Карта первого прохода](../reports/2026-09-30-documentation-map.json) фиксирует
состояние до этой очистки и не является перечнем существующих файлов HEAD.
Краткие важные результаты переезда и восстановления сохранены в
[эксплуатационном отчёте](../reports/2026-09-30-operations-baseline.md).

## Дальнейшее хранение

У каждого сохранённого материала должно быть указанное применение: эталон,
ссылка из актуального решения/отчёта или вход проверки. Завершённый план
временно сохраняется вместе с итогом; при следующем кураторском проходе
устаревший дубль можно убрать из дерева с точной Git-ссылкой в отчёте.
Срок хранения не определяется возрастом файла автоматически.
[Правила сопровождения](../DOCUMENTATION_POLICY_RU.md).
