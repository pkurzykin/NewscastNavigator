# Реорганизация и сопровождение документации

Статус: завершено. Владелец: Павел Курзыкин. Дата: 30 сентября 2026.
Основание: владелец утвердил структуру и поручил реализацию в текущей задаче.

**Goal:** привести документацию действующего сервиса к понятной структуре для
людей и агентов и закрепить её сопровождение в каждой последующей задаче.

**Architecture:** единые основные документы, два входа README/AGENTS,
маршруты по аудитории и назначению, отдельные планы, отчёты и архив.
**Tech Stack:** Markdown, Python stdlib, существующие pytest и GitHub Actions.
**Spec:** [решение о структуре](../../decisions/2026-09-30-documentation-system.md).
**Execution:** координатор выполняет перенос и проверки; ограниченные
документные подзадачи допускаются через PROJECT_AGENTS; независимые review
и verification проверяют один итоговый снимок. Повторное согласование
предусмотренных правок не требуется.

Итог: [отчёт и независимые проверки](../../reports/2026-09-30-documentation-system.md).

## Приёмка и проверки

- Каждый из 100 исходных Markdown учтён, связанные tracked материалы сохранены.
- Нет второй действующей копии требований; README и AGENTS ведут к общим источникам.
- Руководство покрывает рабочий путь редакции, роли, сценарий, производство,
  историю, DOCX и CaptionPanels, без добавления несуществующих возможностей.
- Инструкции содержат условия применения, шаги, проверку и ошибку/восстановление;
  факты прошлых проверок явно датированы и вынесены в отчёты.
- Жизненный цикл плана, обязательное обновление документов и ответственность
  закреплены в policy, AGENTS, PR и шаблонах; CI проверяет ссылки и структуру.
- `python3 -m unittest discover -s scripts/tests -p 'test_check_docs.py'`;
  `python3 scripts/check_docs.py`; релевантные backend policy/evidence tests;
  `git diff --check`; контроль SHA-256 замороженных свидетельств.
- Проверка текущего каталога выполняется также по Git index, чтобы ignored
  локальные файлы не скрывали отсутствие целей в чистом checkout.
- Приложение, серверы и внешние URL не запускаются ради документационного этапа.

## Review Focus

1. Исторические разрешения/незакрытые формулировки не воспринимаются как текущие поручения.
2. Перенос не ломает команды runbooks, относительные ссылки и доказательства старых SHA.
3. Руководство не расширяет права и продукт; закрытый статус не выдумывает проверки.
4. CI действительно ловит недоступные/неучтённые документы, а не только наличие слов.
5. Последующая задача имеет один ясный путь обновления документации и закрытия плана.
