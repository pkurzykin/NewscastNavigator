# Текущее состояние NewscastNavigator

## Состояние продукта

По решению владельца от 30 сентября 2026 сервис работает, вопросы прошлых
этапов закрыты. Первоначальная пересборка, переезд на VDS и создание постоянного
домашнего тестового контура завершены. История этих работ не задаёт новых задач.

Действующие требования — [спецификация](product/SPEC_RU.md) и
[критерии качества](product/EVAL_RUBRIC_RU.md). Пользователю —
[руководство редакции](guides/USER_GUIDE_RU.md).

## Среды и процесс

- Production: Hostland VDS с рабочими данными; инструкции в
  [production runbook](operations/hostland/README.md).
- Постоянная приёмка: домашний LAN-only HTTPS, синтетические данные;
  [домашний workflow](operations/HOME_TEST_WORKFLOW_RU.md).
- Изолированная разработка и тесты: [локальная инструкция](engineering/LOCAL_DEV_WORKFLOW_RU.md).
- Изменение: отдельная ветка → проверки → домашняя приёмка точного commit →
  отдельное разрешение выпуска → проверка результата по [процессу релиза](operations/RELEASE_WORKFLOW_RU.md).

Эксплуатационные сведения в [снимке от 30 сентября](reports/2026-09-30-operations-baseline.md)
относятся к датам указанных проверок. Перед серверной операцией состояние
проверяется заново в разрешённых границах. Этот файл не подтверждает новый deploy.

## Интеграция и продолжение

Общий пакет опубликован в [PR №39](https://github.com/pkurzykin/NewscastNavigator/pull/39).
В этом PR фиксируются проверенные head/base, CI, решение о merge и итог
синхронизации и очистки по мере выполнения соответствующих шагов. Датированные отчёты описывают свои снимки и не заменяют свежую
Git-проверку. После возвращения к задаче куратор сверяет PR и local/origin/remote;
этапы без подтверждения отмечает PENDING/UNKNOWN. Прежние worktree сохранены
с причинами KEEP в отчёте. Порядок — [Git workflow](engineering/GIT_WORKFLOW_RU.md).

Дальнейшие изменения сопровождаются по [стандарту документации](DOCUMENTATION_POLICY_RU.md):
исполнитель обновляет основные документы, куратор проверяет согласованность,
автоматическая проверка контролирует структуру, ссылки и целостность эталонов.

## Продолжение работы

1. Проверить каталог, ветку, HEAD и локальные изменения.
2. Прочитать [AGENTS.md](../AGENTS.md), этот файл и документы по [каталогу](README_RU.md).
3. Использовать текущую задачу и действующие разрешения из разговора.
   Старые «следующие шаги» относятся к своим историческим снимкам.
4. При завершении обновить затронутые источники и сохранить результат по
   [правилам сопровождения](DOCUMENTATION_POLICY_RU.md).
