# Восстановление при недоступности домашнего сервера

## Источники и пределы

Домашний сервер получает зашифрованные копии с VDS. На VDS также остаются
зашифрованные точки БД и полные архивы релиза. USB содержит только
зашифрованную копию ключа `age`; парольная фраза хранится отдельно.
**Одного USB без доступной зашифрованной копии недостаточно.** Если
одновременно потеряны дом и VDS, независимая копия данных пока не
подтверждена. Снимки Hostland нельзя считать таким источником до проверки
их фактического наличия и возможности восстановления.

## Порядок при аварии

1. Установить, работает ли production на VDS. Если работает, не останавливать
   его для восстановления домашнего резервного узла. Если VDS недоступен,
   зафиксировать инцидент и не направлять пользователей на старую домашнюю БД.
2. На доступном VDS или носителе выбрать самую свежую завершённую точку
   `db-…-production.dump.age` и `full-…-production.tar.age` с одинаковым
   `source_commit` из их `.json`-метаданных. Проверить имена, размеры и SHA-256
   обоих ciphertext-файлов. Время точки определяет возможную потерю
   последних изменений. Старые архивы во время инцидента не удалять.
3. На доверенной машине считать `backup.agekey.passphrase.age` с USB и
   расшифровать при скрытом вводе фразы из менеджера паролей. Открытый ключ
   хранить только в закрытом временном каталоге, не переносить на VDS и не
   выводить в журнал или чат. Проверить им расшифровку выбранных архивов.
4. Проверить состав полного архива, `SHA256SUMS`, image manifest и совпадение
   коммита с точкой БД. Восстанавливать только в **пустую** PostgreSQL и с
   проверенными образами релиза. Перед запуском приложения проверить схему и
   содержимое БД; затем health, HTTPS и пользовательский путь. Открытие сайта
   для команды, DNS и любые действия с действующим VDS требуют отдельного
   плана под конкретный инцидент.
5. Удалить временные открытые ключ, дамп, распакованный архив и закрытый
   тестовый стек. Сохранить только результаты проверки и зашифрованные
   исходники.

`RESTORE_PRODUCTION.md` описывает переезд **с работающего дома** 23.09.2026.
Его команды нельзя повторять буквально при утрате дома или на заполненном
production.

## Изолированная репетиция 1C

`rehearse_home_loss.sh` предназначен только для домашнего сервера как
**площадки репетиции**. Источники — ciphertext и метаданные непосредственно
с VDS плюс ключ, восстановленный из файла USB. Штатный открытый домашний
`backup.agekey` и домашние snapshots не используются. Это проверяет цепочку
«VDS + USB → новый Compose-проект», но не заменяет проверку на физически
новом оборудовании.

В частном каталоге
`/home/newscast/private-demo/hostland-backups/restore-checks/home-loss-<id>`
с правами `0700` должны находиться выбранные ciphertext и их исходные
`.json`-метаданные, а также временный `identity.agekey` с правами `0600`.
Кроме того, перед репетицией через отдельный закреплённый
административный SSH к **работающему** VDS нужно проверить релиз
`verify_release.sh` и получить SHA-256 действующего
`/opt/newscast-production/image-manifest.json`. Хеш передаётся скрипту как
`--trusted-manifest-sha256`; брать его из экспортного архива нельзя.
Фраза вводится интерактивно до запуска скрипта, не в аргументах. Команда:

```bash
./rehearse_home_loss.sh \
  --workspace /home/newscast/private-demo/hostland-backups/restore-checks/home-loss-<id> \
  --db-name db-<timestamp>-production.dump.age \
  --full-name full-<timestamp>-production.tar.age \
  --trusted-manifest-sha256 <хеш-из-действующего-релиза-VDS>
```

Скрипт проверяет SHA-256, коммит пары и независимый хеш манифеста образов,
распаковывает архив с проверкой
путей и `SHA256SUMS`, загружает образы и запускает только
`nn-home-loss-drill-1c` с портами на `127.0.0.1`. Перед восстановлением
требует пустую БД. После запуска проверяет схему и число таблиц, рассчитывает
fingerprint восстановленной БД для закрытого отчёта, проверяет HTTPS health
и frontend. Исходный fingerprint для выбранной пятиминутной точки не
записывается на VDS, поэтому побайтовое совпадение с живой БД эта репетиция
не доказывает. Smoke не авторизуется и не проверяет DOCX или CaptionPanels;
правок в сценарии он не вносит. При завершении скрипт удаляет тестовый том,
контейнеры и временные
открытые данные. Результат `HOME_LOSS_DRILL=ok` действителен вместе с
подтверждением очистки и отсутствия тестового проекта.

Скрипт не меняет production, DNS, расписания и политику хранения. На
действующем VDS его не запускать. При реальном инциденте использовать
процедуру выше и отдельный утверждённый план для новой машины.
